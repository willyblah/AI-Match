# 素材可靠性与透明处理规则（V2.3 Asset Reliability Patch）

本规则用于防止**白色角色被误抠成透明**，并保证跨状态角色尺寸真正统一。白色身体、白色耳朵、白色脸部、白色爪子和浅蓝色描边都可能是角色本身，绝不能当作背景删除。

## 一、Alpha-first：先检查透明通道

处理 Sprite Sheet 前，**必须先检查源图片是否已包含有效透明通道**。

若源图片存在有效 alpha，且画布边缘主要是透明区域：

- 直接保留原始 alpha；
- 跳过 RGB 背景抠除；
- **不得**根据透明像素的 RGB 值判断背景；
- **不得**把透明 PNG 四角的黑色 RGB 当成黑色背景。

只有在源图片**没有有效透明通道、且背景颜色明确**时，才允许进行背景移除。

## 二、明确的背景处理模式

背景处理区分为三种模式：

- `preserve-alpha`：保留已有透明通道；
- `chroma`：只处理明确的纯色背景；
- `auto`：无法确定时**不要冒险抠除，必须暂停并报告**。

优先顺序（严格）：

1. 有效 alpha → `preserve-alpha`
2. 明确纯色背景 → `chroma`
3. 无法确定 → 暂停并请求检查

**禁止对所有图片默认执行“自动采样四角颜色并抠除”。**

## 三、修复羽化逻辑

若确实需要处理纯色背景，羽化必须从背景边缘的低透明度逐渐过渡到主体的高透明度，方向为：

`0 → 255`

不能出现“距离背景越远反而越透明”的情况。

源图片已有 alpha 时，**不得重新计算或覆盖原始 alpha**。

## 四、真正统一角色尺寸（canonical body scale）

不要只统一每个格子的 canvas 尺寸。必须建立 canonical body scale：

1. 以 canonical base 或 idle neutral frame 作为角色尺寸参考；
2. 得到 canonical body height 和 body width；
3. 计算每个状态 neutral frame 的实际主体高度；
4. 对整个状态统一应用**同一个** scale correction；
5. 同一状态的所有帧必须**整体一起缩放**，不能逐帧单独 fit；
6. 保持角色底部基线和水平中心一致。

默认使用共享 canonical scale。只有 QA 修复时才允许使用 state-level correction factor，并且必须记录原因。

## 五、素材完整性 QA（Asset Integrity QA）

不能只检查处理后的 bbox、连通分量和 holes。必须比较**处理前（源）与处理后**的：

- 有效 alpha 面积；
- 主体高度；
- 主体宽度；
- 主要连通区域；
- 头部、耳朵和身体内部的 alpha 覆盖率。

若处理后主体面积或高度发生**灾难性减少（约减少 50% 以上）**，必须直接判定 blocker，禁止接入应用。

还必须检查：

- 黑色角色不能被抠除；
- 白色角色不能被抠除；
- 角色内部不能出现棋盘格透明洞；
- 不能出现黑色线稿；
- 不能出现白色贴纸外壳；
- 不能出现异常的边缘膨胀；
- **不能仅因为剩余部分几何一致就判定通过。**

## 六、失败处理

若素材处理导致角色主体明显损坏：

- 停止继续处理当前损坏 PNG；
- 回到对应状态的原始未处理素材；
- 只重新处理失败的状态；
- 不要重新生成 canonical base；
- 不要修改已经合格的状态；
- 不得使用 SVG、CSS、Emoji 或手写图形替代。
