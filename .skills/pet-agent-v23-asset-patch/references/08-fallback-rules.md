# 失败与降级规则

> **核心原则**：宠物是目标应用的正式视觉资产。任何环节失败时，**优先重试/修复正式资产**；无法得到合格正式资产时**停止宠物接入并报告**，绝不使用 SVG、CSS 圆点、图标、Emoji、纯色圆点、临时占位角色或手写代码冒充正式宠物继续接入。
>
> **禁止的替代物**：
> - 手写 SVG 角色
> - CSS 拼出的猫、狗、人物或几何图形
> - Emoji 或 Unicode 符号
> - Lucide / 图标库图标
> - 纯色圆点、方块、几何体
> - 未经 QA 的静态占位图或临时矢量角色
> - 图片生成失败后直接写一个“简单矢量角色”
>
> **降级范围**：只读降级（§3）仅适用于无法安全绑定业务 Action 的场景，不能用于图像资产生成失败。图像资产失败必须按 §4、§5、§6 处理。

## 0. 用户未确认制作方案

### 场景

- 用户只说“我想要一只橘猫”“帮我加个宠物”或上传参考图，但未明确确认完整制作方案。
- 用户回复包含修改要求，尚未确认更新后的确认单。

### 处理

- **停止执行**：不调用任何图片生成能力，不生成 canonical base，不生成 Sprite Sheet，不修改代码。
- **不制作临时宠物**：禁止用 SVG、CSS、Emoji、图标、纯色圆点或手写代码临时冒充宠物。
- 等待用户明确回复“确认”“开始”“可以”“没问题”等肯定词后，才进入正式制作流程。

## 1. 项目理解失败

### 场景

- 无法读取目标项目文件。
- 找不到主页面或业务状态。
- 项目结构异常，无法识别应用类型。

### 处理

- 停止所有代码修改和图片生成。
- 向用户询问："你希望把宠物接入哪个应用或页面？"
- 在获得明确上下文前不继续执行。

## 2. 业务状态推断失败

### 场景

- 找不到状态枚举或状态机。
- 找到的多个状态机无法确定主状态。
- 业务状态语义模糊。

### 处理

- 停止自动生成，不修改代码。
- 向用户说明已发现的候选状态，请用户选择或确认。
- 只根据用户明确选择的状态继续。

## 3. 安全操作找不到

### 场景

- 项目中没有明显的 `start/pause/resume/reset` 等函数。
- 按钮 onClick 指向复杂逻辑，无法安全绑定。

### 处理

- 宠物降级为只读状态反馈宠物。
- 点击气泡只显示状态和话术，不生成操作按钮。
- 告知用户："当前未找到适合宠物绑定的安全操作，宠物只会反馈状态。"
- **注意**：这是交互能力的降级，不是用占位角色替代正式宠物。正式宠物资产仍须正常生成并通过 QA。
- **适用范围**：只读降级仅适用于业务 Action 无法安全绑定，**不适用于图像资产生成失败**。图像素材失败仍按 §4、§5、§6 处理，无法得到合格正式资产时停止接入。

## 4. Canonical Base 失败

### 场景

- canonical base pet 生成结果不符合角色方向或应用画风。
- 多次重新生成仍无法得到合格的 canonical base。

### 处理

- 重新生成或修复 canonical base（调整提示词、强化角色参考与应用画风参考的使用）。
- 如果自动修复无法解决，且 canonical base 明显违反用户确认的角色方向、应用画风或身份要求，才暂停并请求用户意见。
- **无法得到合格 canonical base 时，停止宠物接入**，向用户报告失败原因。
- **禁止**：使用 SVG、CSS 纯色圆点、图标、Emoji、手写代码、临时占位角色或任何非官方图片生成能力继续接入。

## 5. 单个 Sprite 状态失败

### 场景

- 某个状态的生成结果不符合要求。
- 某个状态处理失败或帧数识别失败。
- 某个状态与 canonical base 不一致（几何 QA 或 Character Identity QA 失败）。

### 处理

- **只重新生成或修复失败的那个状态**。
- **不重做已通过 QA 的其他状态**。
- 如果必要状态（如 idle、working）仍然失败，**停止最终接入并报告失败状态**。
- **禁止**：用未经 QA 的静态占位图冒充该状态。

### 状态共享

如果业务允许多个状态共享同一视觉动画，**只能复用已经通过 QA 的正式状态资产**，并在状态映射中明确记录（如 `idle` 与 `paused` 共用 `idle.png`）。**不能临时生成占位角色**来填充缺失状态。

## 6. Sprite 处理失败

### 场景

- `process_sprites.py` 无法识别帧数。
- 背景去除不净、输出文件异常或为空。
- 几何规范化失败。

### 处理

- 先检查帧数配置、背景处理、切帧和 canonical geometry 是否正确。
- 尝试修复处理流程（调整参数、重新生成该状态源图）。
- **仍失败时，停止动画接入并报告**。
- **禁止**：自动切换成手写 SVG 或 CSS 宠物继续接入。

## 7. 运行时正式资源加载失败

### 场景

- 运行时图片 404 或解码失败。
- 网络问题导致资源加载失败。

### 处理

- 宠物组件使用 React Error Boundary 隔离。
- **隐藏宠物**（不渲染或渲染空），保持主应用继续运行。
- 可保留一个轻量的"重新加载宠物"入口，便于用户重试。
- **禁止**：用另一套占位角色（SVG 图标、CSS 圆点等）替代正式宠物。

## 8. 接入后构建失败

### 场景

- 接入宠物组件后 lint 失败。
- 接入后 TypeScript 类型检查失败。
- 构建报错。

### 处理

- 优先修复本轮改动引起的问题。
- 如果无法安全修复，回退本轮对目标项目的修改。
- 不修改主业务逻辑来适配宠物组件。

## 9. 宠物组件运行时报错

### 场景

- 坐标计算越界。
- 动画播放异常。
- 气泡渲染异常。

### 处理

- 宠物组件使用 React Error Boundary 包裹。
- 组件错误时自动隐藏宠物。
- 主应用继续正常运行。

## 10. 用户撤销或修改

### 场景

- 用户确认方案后希望修改。
- 用户希望取消接入。

### 处理

- 修改方案后重新输出确认单，再次确认。
- 用户取消时，停止执行并清理已生成的临时文件（未注册/未集成到主应用的部分）。
- 不删除用户已有的项目文件。

## 11. 禁止的降级方式（FORBIDDEN）

以下降级方式**一律禁止**，不得作为任何失败场景的兜底：

- ❌ CSS 纯色圆点
- ❌ SVG 占位图标
- ❌ 未经 QA 的静态占位宠物
- ❌ 图片失败后自动手写矢量角色（SVG/CSS 几何拼凑）

正式宠物失败时，正确做法是**重试/修复正式资产**；仍失败则**停止接入并报告**。

## 12. 禁止声明

Skill 不得向用户宣称：

- "100% 安全"
- "绝对不会影响主应用"
- "零侵入"

应使用：

- "低侵入接入"
- "已通过 Error Boundary 隔离，主应用风险较低"
- "失败时会优先降级或回退"

## 13. 回退操作清单

如果需要回退本轮改动，按以下顺序执行：

1. 删除 `src/components/pet/` 目录下新增文件。
2. 删除 `public/images/pet/` 目录下新增资源。
3. 恢复主页面中被修改的挂载代码。
4. 恢复 `src/hooks/` 中仅因宠物接入放宽的守卫（如有）。
5. 运行 lint 验证主应用可正常构建。
