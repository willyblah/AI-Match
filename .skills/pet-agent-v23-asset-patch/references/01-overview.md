# 应用宠物 Agent 设计原则

## 1. 什么是应用宠物 Agent

应用宠物 Agent 是**嵌入目标秒哒应用内部的陪伴式应用宠物**，是一个低侵入、可交互、有视觉状态的页面组件。它**不是**系统级桌面宠物、独立桌宠应用或通用游戏角色系统，也不跨出应用窗口。它能够：

- 根据目标应用的业务状态自动切换动画。
- 在重要状态变化时自动出现气泡反馈。
- 用户点击时查看当前状态、关键指标和允许的操作。
- 支持拖拽移动和位置记忆。
- 不替代主应用功能，而是增强主应用的情感反馈。

## 2. 核心设计原则

### 2.1 项目分析优先

调用 Skill 后，先读取目标应用代码，而不是立即生成图片。

- 自动识别应用类型、主页面、业务状态、安全操作函数。
- 能推断的信息不询问用户。
- 只向用户确认无法推断或存在歧义的信息。

### 2.2 阻断条件

真正阻断项只有三个：

1. 无法访问目标应用上下文。
2. 宠物角色来源不明确。
3. 用户未明确确认《应用宠物制作确认单》。

其他信息（状态数量、性格、提醒规则）均可自动推荐并在确认单中列出，由用户一次性确认。

在获得用户明确确认前，禁止调用任何图片生成能力、生成 canonical base、生成 Sprite Sheet 或修改代码。

### 2.3 角色基准唯一

- 如果用户有参考图，以参考图作为 canonical reference。
- 如果用户只有文字描述，先形成统一的 canonical base pet。
- 后续所有状态动画都基于同一个角色基准生成，保持画风、比例、身份一致。

### 2.4 业务状态与视觉状态分离

- 目标应用的业务状态可能有很多（如番茄钟的 idle/running/paused/completed/resting）。
- 宠物视觉状态应控制在 4 个左右，最多 4–6 个。
- 多个业务状态可以共享同一个视觉动画，但使用不同气泡话术。

例如番茄钟中，idle、paused、resting 都映射到 `idle` 动画，但气泡话术不同。

### 2.5 临时事件模型

remind 等短暂状态不是长期业务状态，而是覆盖在基础视觉状态之上的临时事件。

- 有触发条件、持续时间、用户操作、冷却时间。
- 结束后自动恢复基础视觉状态。
- 典型场景：专注超时、生成卡顿、任务快到期、连续答错。

### 2.6 只调用安全操作

宠物按钮只能调用目标应用已经存在的函数。禁止默认绑定删除、支付、发布、账号权限等高影响操作。

### 2.7 失败不破坏主应用

- 单个动画状态失败只重试该状态。
- 宠物组件用 Error Boundary 隔离。
- 资源加载失败时隐藏宠物，不用占位角色替代正式宠物。
- 构建失败时优先修复，无法安全修复则回退。
- 详见 `references/08-fallback-rules.md`。

## 3. V0 默认人格

> 友好、简短、轻度活泼、有陪伴感，但不过度打扰用户。

如果用户未指定，直接使用此默认人格。

## 4. 默认视觉状态

| 状态 | 含义 | 默认动画 |
| --- | --- | --- |
| idle | 等待、未开始、暂停、休息 | 循环 |
| working | 运行中、处理中、生成中 | 循环 |
| success | 完成、成功 | 单次播放 |
| remind | 临时事件（疲劳/超时/提醒） | 单次或循环 |

允许根据应用调整为：idle / thinking / success / encourage / failed 等。

## 5. 默认行为参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| 自动气泡运行中 | 3000ms | 开始专注/运行中时 |
| 自动气泡暂停 | 3000ms | 业务状态暂停时 |
| 自动气泡完成 | 5000ms | 成功/完成时 |
| 自动气泡提醒 | 5000ms | 临时事件触发时 |
| 临时事件持续 | 5000ms | remind 显示时长 |
| 正常模式冷却 | 15 分钟 |  remind 冷却 |
| 测试模式冷却 | 10 秒 | 便于快速验证 |
| 拖拽点击阈值 | 5px | 移动超过 5px 视为拖动 |

这些参数可根据应用调整。

## 6. 与其他 Skill 的关系

- 与秒哒平台提供的「图片生成与编辑（超级版）」Skill 协作：生成角色基准和 Sprite Sheet。
- 与 `visual-design-director` 协作：在应用整体风格确认后，生成宠物风格参考。
- 与 `magic-ui-motion` 协作：未来可增强宠物入场、气泡动效等。

## 7. 不适宜使用本 Skill 的场景

- 只需要一个静态图标或装饰图。
- 目标是桌面系统级宠物、全局悬浮窗或独立桌宠应用（本 Skill 生成的是**应用内陪伴宠物**）。
- 需要宠物自主行走、审阅等与目标应用无关的状态。
- 需要复杂 AI 对话、语音交互、宠物养成、商城系统。
- 需要系统通知或多宠物同时存在。
