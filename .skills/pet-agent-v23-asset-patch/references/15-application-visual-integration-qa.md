# Application Visual Integration QA（V2.2 新增）

确保宠物作为目标应用的正式视觉资产，与现有插画/人物/UI 系统属于同一套视觉语言，并在实际页面中协调呈现。**该 QA 不能只检查透明度和 bounding box，必须在真实应用页面预览中进行视觉判断。**

## 1. 检查维度

### 1.1 视觉系统一致性

- 宠物是否与应用现有的人物、角色、场景插画属于**同一视觉系统**（像由同一位设计师、用同一套视觉语言绘制）。
- 色彩、饱和度、明度是否与应用主色调一致。
- 描边：有无、粗细、颜色是否与应用插画一致。
- 阴影、渐变、材质、高光风格是否一致。
- 形状语言（圆角、几何特征、简化比例）是否一致。
- 留白与构图密度是否与应用整体风格匹配。

### 1.2 风格漂移检测

- 宠物是否看起来像**外部贴纸**（明显不属于本应用的素材）。
- 是否像通用吉祥物、贴纸、3D 玩偶或照片素材。
- 是否使用了与应用画风冲突的渲染风格（如应用是扁平矢量，宠物却是写实/3D）。

### 1.3 页面集成协调性

- 宠物在实际应用页面中的**尺寸、位置、视觉重量**是否协调。
- 是否遮挡输入框、主要按钮、导航、关键内容。
- 移动端小尺寸下宠物是否仍清楚可辨。
- 宠物的状态动画节奏是否与应用整体节奏协调。
- 气泡和双击反馈是否破坏应用整体风格（颜色、圆角、阴影、动效）。

### 1.4 边界与冲突

- 应用截图中是否出现宠物越界、裁切或视觉冲突。
- 宠物是否与页面其他元素产生视觉打架（颜色相近、层级混乱）。

## 2. 执行方式

1. 将宠物接入真实应用页面后，在**实际页面预览**中观察（而非仅看独立 Sprite）。
2. 桌面端与移动端各检查一次。
3. 触发各业务状态、双击 reaction、气泡，观察动态表现是否协调。
4. 与应用现有插画/人物并置对比，判断是否属于同一视觉系统。

## 3. 失败处理

如果 Application Visual Integration QA 失败：

1. **先判断问题来源**：角色设计 / 配色 / 素材风格 / 尺寸 / 位置 / 接入层。
2. **只修复失败范围**：
   - 尺寸/位置问题 → 调整接入层（容器尺寸、定位、层级）。
   - 动效节奏/气泡风格问题 → 调整 reaction/气泡样式。
3. **如果角色本身属于另一套视觉语言**（风格漂移），应**重新生成相关正式资产**（强化应用画风参考的使用），而不是掩盖问题。
4. **禁止**：通过简单缩小或降低透明度来掩盖根本的画风不一致。

## 4. QA 检查项

- [ ] 宠物与应用现有插画/人物属于同一视觉系统
- [ ] 色彩、饱和度、描边、阴影、渐变、材质一致
- [ ] 宠物不像外部贴纸、通用吉祥物、3D 模型或照片素材
- [ ] 桌面端尺寸、位置、视觉重量协调
- [ ] 移动端小尺寸下仍清楚可辨
- [ ] 不遮挡输入框、主要按钮、导航、关键内容
- [ ] 状态动画节奏与应用协调
- [ ] 气泡和双击反馈不破坏整体风格
- [ ] 无越界、裁切或视觉冲突
