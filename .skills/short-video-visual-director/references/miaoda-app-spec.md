# 秒哒应用规格：短视频视觉导演工作台

## 必须实现

1. 创作入口：主题/产品、传播目的、平台、时长、受众、目标情绪、品牌约束、参考说明，以及可选参考图/视频/音频上传。
2. 核心操作：显著的“生成视觉方案”按钮，真实调用 `@文本生成大模型`；提交期间展示进度，失败显示原因与重试，不清空用户输入。
3. 结果总览：一句话创意、主辅风格、选择理由、色板、光线、材质、构图、镜头运动、字幕、转场和禁用项；颜色必须可视化为色块。
4. 分镜预览：按时间顺序展示镜头卡和时间轴；每镜包含画面、动作、景别、机位、运动、声音触发、转场、素材来源和可复制生成提示词。
5. 局部重生成：允许只重生成视觉方向或单个镜头，保持用户锁定的字段不变；不能每次推翻全部结果。
6. 项目设置：画幅、时长、FPS、BPM、每小节拍数可调整；调整后重新计算节拍，不静默覆盖已编辑分镜。
7. 分镜编辑器：支持增删、拖动排序、字段编辑和锁定；提示词支持单条及全部复制。
8. 检查面板：标记色板冲突、时长重叠/空洞、缺失声音触发、混用画幅和字幕越过安全区。
9. 导出：JSON 和 CSV；不得只显示“导出成功”，必须触发真实下载。

首次打开提供一个可直接点击的示例简报，但不得自动填充假结果。空状态应引导用户先输入简报并生成，而不是展示大量空字段。

## 禁止的运行期实现

- 不得从应用执行 `scripts/beat_grid.py` 或任何 Python/shell 命令。
- 不得依赖 Skill 目录、`/Users/...`、本机临时目录或生成 Agent 的文件系统。
- 不得在 Edge Function 中启动子进程；Edge Function 使用 TypeScript/Deno。
- 不得把脚本执行失败作为用户使用节拍计算器的前提。
- `beat_grid.py` 仅用于 Agent 验证公式；应用运行期必须使用下方 TypeScript 公式。

## 数据与平台能力

- 单人临时工具默认用前端状态和浏览器持久化，不强制 Supabase。
- 用户要求登录、跨设备或项目历史时，使用 Supabase Auth + Database，所有表带 `user_id` 并启用 RLS。
- 上传参考图、视频或音频时使用 Supabase Storage；列表展示缩略图/播放器、上传进度和删除操作。
- 只有调用第三方生成服务时才使用 Edge Function；密钥只在服务端，异步媒体遵循创建、轮询、预览、转存和下载闭环。
- 文本模型返回内容必须按 [大模型输出契约](llm-output-contract.md) 解析并校验；解析失败可请求模型修复一次，仍失败则保留原始错误并允许用户重试。

建议数据结构：`projects`、`visual_bibles`、`storyboard_shots`、`media_assets`。分镜按 `sort_order` 排序；保存使用乐观更新并显示失败重试。

```ts
const secondsPerBeat = 60 / bpm;
const secondsPerBar = secondsPerBeat * beatsPerBar;
const frameAtBeat = (beat: number) => Math.round(beat * secondsPerBeat * fps);
```

必须校验正数；小数秒只用于显示，剪辑定位以舍入后的整数帧为准。

运行期验收用例：`bpm=120, fps=30, beatsPerBar=4, bars=2` 应得到 `secondsPerBeat=0.5`、`secondsPerBar=2`、总时长 `4秒`、末尾帧 `120`。该用例在前端自动测试或开发期断言中通过后再交付。
