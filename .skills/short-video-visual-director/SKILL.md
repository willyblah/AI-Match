# 短视频视觉导演（秒哒中文版）

先决定作品应该呈现什么、为何这样呈现，再进入素材生成与剪辑。目标不是堆叠“电影感”词汇，而是让色彩、光线、材质、构图、运动、声音和剪切共同执行同一个创意命题。

## 前置条件

- 直接在对话中提供视觉策划时无需外部依赖。
- **生成秒哒应用时必须组合 `@文本生成大模型`（slug：`wenxin-text-generation`）**。视觉方向、分镜和提示词属于开放式生成能力；缺少模型时应用只会成为手工表单，不构成完整产品。
- 用户要求真正生成图片或视频时，再检索并组合当前可用的秒哒媒体生成 Skill；不得猜测 Skill 名称。默认候选需从实时 Skill 清单确认，不能仅凭本文件硬编码。
- 用户只需要方案时，不新增生成接口、Supabase 或 Edge Function。
- 用户需要保存项目、素材和历史版本时，使用 Supabase；按登录用户隔离数据，媒体进入 Storage。

## 核心工作流

1. 从用户素材中提炼目的、受众、平台、画幅、时长、声音结构、品牌约束和目标情绪。缺失信息不影响主方向时，以可见假设先出首版。
2. 写一句创意命题，并选择一个主风格与最多一个辅助风格。
3. 建立视觉圣经：色板、光线、材质、构图、景别、镜头运动、字幕、转场、声音触发及禁用项。具体方法见 [视觉系统](references/aesthetic-system.md)。
4. 根据音乐段落、BPM、旁白语义或情绪转折建立时间网格。Agent 在生成期验证节拍数据时运行：

   ```bash
   python3 scripts/beat_grid.py --bpm 120 --fps 30 --beats-per-bar 4 --bars 8 --json
   ```

   `scripts/beat_grid.py` 只供 Skill 的 Agent 生成期/任务执行期使用，不能复制到秒哒应用运行期，也不能让浏览器、Supabase Edge Function 或用户设备调用 Python、shell、FFmpeg 或本地文件路径。生成应用时必须将相同公式改写为前端 TypeScript；应用部署后不依赖 Skill 包内脚本。

5. 生成时间轴分镜。每镜必须包含时间码、画面动作、景别/机位/运动、声音触发、转场、素材来源和生成提示词。
6. 若调用媒体生成能力，对所有素材复用同一视觉圣经和人物/产品锚点；批量生成、严格筛选，拒绝风格漂移。
7. 进行成片诊断：保留项、失焦项、逐镜修改、优先级、预期收益。漂亮但不属于本片的镜头也应删除。

## 秒哒应用生成要求

用户要求“做一个视觉导演应用/工具”时，读取 [秒哒应用规格](references/miaoda-app-spec.md) 和 [大模型输出契约](references/llm-output-contract.md) 并完整实现，不得只生成介绍页、空白编辑器或静态表单。默认主链路必须是：输入创意简报/上传参考 → 一键生成完整视觉方案 → 展示视觉方向卡与时间轴分镜 → 用户修改或局部重生成 → 复制提示词/导出。生成按钮必须真实调用文本生成大模型，不能用前端固定模板伪造结果。

**运行期技术边界：** 生成的秒哒应用只能依赖平台实际提供的前端、Supabase、Edge Function、Storage 和已组合 Skill。Skill 包中的 Python 脚本不会随应用部署，不得在应用代码中出现 `python3 scripts/beat_grid.py`、`child_process`、shell 命令或 `/Users/...` 本地路径。节拍功能必须由浏览器 TypeScript 即时完成，并至少用 `120 BPM / 30 FPS / 4拍 / 2小节 = 4秒、末帧120` 做运行期单元校验。

## 执行优先级

1. 用户已有素材和品牌约束优先于预设审美。
2. 一致性优先于新奇；主风格只有一个，辅助风格最多一个。
3. 硬切落在节拍、瞬态或语义转折；不要为了炫技增加转场。
4. 提示词必须描述可见内容、镜头语言、光线、材质、色彩和运动，避免只写“高级感”。
5. 不直接模仿在世创作者的独特风格；将参考拆成可执行的通用视觉特征。
6. 输出必须能交给拍摄、素材生成或剪辑直接执行。

## 沟通规则

- 先给创意方向和选择理由，再给分镜与提示词。
- 明确标注用户事实、创作假设和可替换项。
- 若提供节拍表，写明 BPM、FPS、拍号和舍入方法。
- 若媒体生成能力未接入，仍完整交付提示词与素材清单，不虚构生成结果。

## 常见坑

- 多种互相冲突的风格混在同一作品。
- 固定套用原项目的 138 BPM、9:16 或 angelcore 色板。
- 把示例 Remotion/FFmpeg 代码当成所有项目的强制实现。
- 只生成任务或素材 ID，没有预览、保存与下载闭环。
- 为纯策划任务无条件引入数据库、接口或媒体 Skill。
- 把核心大模型错误地做成可选项，导致生成应用只有空表单，没有自动产出能力。
- 在生成应用中调用 Skill 包内 Python 脚本；这些脚本只存在于 Agent 生成环境，不会部署到浏览器或 Edge Function。
