# Kling API 错误处理

必须同时检查 HTTP 状态和 JSON `code`。只有 HTTP 成功且 `code=0` 才是业务成功。

## 秒哒应用错误透传

创建或查询 Edge Function 不得将所有异常统一转换为“未知错误”。应返回结构化 JSON，并保留安全的诊断字段：

```json
{
  "error": "安全的用户提示",
  "code": 1200,
  "message": "上游错误信息",
  "request_id": "request-id"
}
```

字段规则：

- `error`：面向用户的安全提示，必须存在；
- `code`：上游业务码（如存在）；
- `message`：上游 message（如存在），不得包含密钥或内部凭据；
- `request_id`：上游请求 ID（如存在），用于定位问题；
- HTTP 状态：保留上游状态；网络异常使用 502/504，并标记 `gateway_error` 或 `upstream_unavailable`。

前端解析 JSON 后展示 `error`，并将 `code`、`request_id` 和 HTTP 状态用于诊断；不得把完整原始响应、Authorization、API Key、网关内部 URL、API ID、计费字段或 Plugin 配置展示给用户。

| HTTP | 业务码 | 含义 | 处理 |
|------|--------|------|------|
| 200 | 0 | 成功 | 创建接口记录 `data.id`；查询接口按 `data[].id` 精确匹配 |
| 401 | 1000–1004 | 鉴权失败、为空、非法、未生效或过期 | 不重试，检查 API Plugin 服务端配置 |
| 429 | 1100–1102 | 账户异常、欠费或资源耗尽 | 不自动重试 |
| 403 | 1103 | 接口或模型无权限 | 不重试，核对 API Center 权限 |
| 400 | 1200–1201 | 请求参数非法 | 修正参数后重新发起 |
| 404 | 1202–1203 | Method、模型或资源错误 | 核对 API Plugin 路由和 `model` |
| 400 | 1300–1301 | 平台或内容安全策略 | 提示修改输入，不自动改写重提 |
| 429 | 1302–1303 | 速率、并发或 QPS 超限 | 查询可退避；创建不自动重提 |
| 429 | 1304 | IP 白名单限制 | 不重试，联系管理员 |
| 500/503/504 | 5000–5002 | 临时服务故障或超时 | 查询可退避；创建保留失败记录，不自动重提 |

## 重试原则

### 查询接口

- 1302、1303、5000、5001、5002 可指数退避重试；
- 401、403、参数错误和内容安全错误不重试；
- 查询不会创建新媒体任务，但仍应控制频率。

### 创建接口

当前 API Plugin 的创建接口没有登记 `external_task_id`。网络错误、超时或无法确认响应时，不自动重试创建请求；保留请求参数、时间和错误信息，由后端确认后再决定是否重新发起。

### 下载和转存

下载失败不代表生成失败。继续使用原任务返回的 URL 重试下载或转存，不得重新创建视频任务。
