# 应用集成规范（生成健身类应用时）

以下是从本技能生成的**任何应用**都必须遵守的**硬性要求**。内容刻意写得具体，以便一次生成就是对的。

---

## 一、平台技能集成矩阵

在**生成阶段**就直接集成，不要自行重复实现这些能力。

**注意「适用条件」列**：只有应用确实包含该功能时才需要集成对应技能；**不要为了满足本表而额外增加应用不需要的功能**。

| 需求 | 必须集成 | 适用条件 | 说明 |
| --- | --- | --- | --- |
| 生成训练方案 / 复盘 / 建议文本 | `@文本生成大模型` | **始终适用** | 禁止自行拼接大模型接口 |
| 导出方案为 Word | `@Word` | 仅当有 Word 导出功能 | 禁止自行手写 `.docx` 生成 |
| 导出 / 打印方案为 PDF | `@PDF` | 仅当有 PDF 导出／打印功能 | 禁止自行手写 `.pdf` 生成 |
| 训练日志导入导出（`.xlsx` / `.csv`） | `@Excel` | 仅当有表格导入／导出功能 | 解析须遵循第二节 |

不作要求：动作示范图的图片生成类技能（生成的动作图可能不准确甚至造成受伤风险 —— 请用文字要点，或产品自有的正规素材）。

进度图表请在前端用常规图表库渲染；简单图表不要引入数据分析流水线。

> 大多数健身应用的核心闭环是「输入条件 → 生成方案 → 展示 → 记录 → 复盘」，其中只有**文本生成**是必需的。导出与表格导入属于可选功能，没有就不要加。

---

## 二、文件解析与导出红线

| 文件类型 | 必须这样做 | 严禁这样做 |
| --- | --- | --- |
| `.xlsx` / `.xls` | 服务端（Edge Function）用 **SheetJS**（`npm:xlsx`）解析二进制 | 用 `TextDecoder` 把二进制当文本读（必然乱码） |
| `.csv` | **状态机**逐字符解析并跟踪引号状态；自动探测分隔符 | `split(',')` |
| `.pdf` | 调用模型前先用 **`pdfjs-dist`** 逐页提取文本，并**校验非空** | 传空字符串占位给模型 |
| `.docx` | 交由 `@Word` 处理 | 把 ZIP 字节当 UTF-8 解码 |

其他规则：

- `.xlsx` 与 `.docx` 都是 **ZIP + XML** 容器，必须解压；原始字节永远不是文本。
- 表头不一定在第一行。应扫描前若干行，按已知字段概念匹配定位表头；**禁止硬编码行号**。
- 匹配前先标准化列名（去括号内容、去空格、转小写），再与**可扩展的别名表**做模糊匹配。
- 失败时抛出**具体、可操作**的错误（缺哪一列、卡在哪一步）。禁止只报"文件格式不正确"，也禁止带着乱码或空内容继续走后续流程。

---

## 三、存储与数据隔离

- **所有存储桶必须私有**。导出的方案通过**签名 URL（短过期）**下载，严禁使用公开桶。
- 若应用有登录 / 多用户，训练日志、方案、身体指标**必须启用 RLS 并按 `user_id` 隔离**。
- 身份一律取自已登录会话；禁止接受客户端传入的 `user_id` 作为过滤条件。

---

## 四、大模型输出校验

- **禁止**用正则从模型返回里抠出 JSON 后直接 `JSON.parse` 就投入使用。
- 必须做 **schema 校验**（字段存在性与类型）；校验失败则重试或明确报错。
- 组数、次数、负荷、时长等数值字段必须做合理区间校验，再入库或展示。

---

## 五、健康数据合规

健康生理数据属**敏感个人信息**。

- 收集身体指标、损伤史、健康状况前，必须取得**单独、明确的同意**。
- **最小必要**：不默认收集体重、体脂、围度，设为可选项。
- 提供用户**自有数据的删除与导出**能力。
- 明确并告知**留存策略**。
- 任何内容送 `@文本生成大模型` 前，**去除或脱敏**可识别身份的信息，只传方案所需字段。

---

## 六、界面必须展示的安全提示

以下内容不能只存在于 prompt 里，必须在应用界面中渲染出来。

1. **免责声明**，首次进入与方案页均需可见：

   > 以上为通用健身教育与计划支持，不构成医疗建议、物理治疗、诊断，也不能替代线下教练。

2. **急症停止运动提示**，需常驻可访问：

   > 出现胸痛、晕厥、严重气促、突发眩晕、急性损伤或异常剧痛时，请立即停止运动并就医。

3. **就医确认提示**：用户填报慢性疾病、孕期／产后、近期手术或明显损伤时触发。

---

## 七、内容禁止项（在生成侧拦截）

- **不承诺结果**：界面文案与生成内容都不得给出具体减脂斤数、增肌量或表现提升幅度。
- **不生成 PED / 类固醇 / 违禁物质方案**，任何形式都不行。
- **不鼓励带痛训练**：锐痛、胸痛、神经症状或急性损伤状态下不得建议继续训练。
- **不给极端热量限制、脱水、兴奋剂或诱发进食障碍的建议。**
- **不为初学者安排极限强度方案。**
- 不诊断损伤、不开康复处方、不推翻医生医嘱。

---

## 八、自检清单

- [ ] 文本生成走 `@文本生成大模型`，无自行拼接的模型接口
- [ ] Word / PDF 导出走 `@Word` / `@PDF`
- [ ] `.xlsx` 用 SheetJS 解析，未用 `TextDecoder` 读二进制
- [ ] CSV 用状态机解析，分隔符自动探测
- [ ] PDF 用 `pdfjs-dist` 提取文本并校验非空
- [ ] 表头通过扫描 + 别名匹配定位，无硬编码行号
- [ ] 所有存储桶私有，导出用签名 URL
- [ ] 多用户已启用 RLS 并按 `user_id` 隔离
- [ ] 大模型输出已做 schema 校验，数值区间已校验
- [ ] 健康数据取得单独同意，身体指标为可选，支持删除导出
- [ ] 免责声明与急症停止运动提示已在界面展示
- [ ] 无效果承诺、无 PED 内容、无带痛训练建议
- [ ] 失败报错具体、可操作
