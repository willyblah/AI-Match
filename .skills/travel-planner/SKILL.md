# 旅行规划助手

## 最高执行优先级：外部 Skill 检索与生成期组合

1. **改写本 Skill 前，必须先检索秒哒 Skill 和 MeDo Skill 中的相关候选能力**，阅读候选 Skill 的名称、description、能力边界和依赖说明，再根据当前 Skill 的真实工作流判断是否实际用到。只有确认当前 Skill 需要的外部 Skill，才在本 Skill 中声明生成应用时自动 `@` 调用及其具体职责；未用到的 Skill 不得添加。
2. **当前 Skill 确实需要并必须自动调用 `@文本生成大模型`**，用于旅行规划、目的地比较、预算解释、行程文本和清单生成。
3. **条件性自动调用搜索 Skill**：如果当前用户需求需要核实签证、入境、天气、交通、景点营业时间、票价或旅行警告等实时目的地事实，先检索当前可用的秒哒/MeDo 搜索 Skill，再在生成应用时自动调用已确认的搜索 Skill；不预先假设名称为 `@baidu-search`，需求不需要实时核验时不调用。
4. 当前 Skill 不处理 Word、PDF 或 Excel 文件，不声明或接入任何文件处理 Skill，也不为此新增文件解析或转换功能。
4. 禁止在生成应用中自行拼接大模型接口。

## 1. 适用范围
支持目的地研究、个性化行程、预算拆分、打包清单、文化礼仪和出发准备时间线。实时信息必须由生成期 Agent 使用可用搜索能力核实；本 Skill 不提供航班、酒店、地图、天气、汇率或预订 API。

## 2. 生成应用工作流
收集最小必要信息：目的地、日期或灵活日期、人数、预算和币种、是否包含机票/住宿、旅行节奏、同行人、兴趣、饮食过敏、无障碍和健康需求。

生成时区分用户输入、模型建议、外部事实、估算和待确认项。行程按地理位置分组，保留移动、排队、用餐和休息缓冲。

## 3. 实时研究规则
签证、入境、健康、旅行警告和法律信息优先使用政府/使领馆/官方机构；交通、景点开放时间和票价优先使用运营方官网。每条时效性信息显示来源、查询日期、适用地点和时区。无法核实时标记“需确认”，不提供保证性结论。

详细规则见 `references/travel-research.md`。

## 4. 预算与清单
预算必须显示币种、人数、是否包含机票/住宿/税费/保险和假设。没有带日期的汇率来源时，不跨币种直接合计。打包清单结合天气、活动、行李规则、饮食、过敏和无障碍需求。

详细规则见 `references/itinerary-and-budget.md`。

## 5. 隐私与数据
如果生成的应用保存偏好、旅行、支出、健康、过敏或无障碍信息：

- 使用应用自身后端，不使用本机隐藏目录；
- 只收集完成功能所需的最小数据；
- 保存敏感信息前单独取得同意；
- 支持查看、编辑、导出和删除；
- 不保存 token、内部密钥或完整搜索上下文。

## 6. 文化礼仪
文化礼仪只能作为研究提纲，必须按国家、城市、具体场所和日期复核。不要按大洲、宗教或性别做绝对化结论。场所现场规则和官方要求优先。

详细规则见 `references/cultural-etiquette.md`。

## 7. 输出格式
每份规划至少包含：

1. 行程概要和日期/时区；
2. 每日安排、移动缓冲和待确认项；
3. 预算表及币种/包含项/假设；
4. 打包清单；
5. 文化礼仪和安全提醒；
6. 来源、查询时间和限制；
7. 用户需要自行确认的预订、签证和官方信息。

## 8. 明确不支持
本 Skill 不自动预订、不支付、不申请签证、不生成虚假确认号，不保证最低价格、签证通过、天气、安全或景点可用性。
